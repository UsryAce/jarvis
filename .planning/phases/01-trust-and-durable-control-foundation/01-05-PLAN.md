<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process/connection -> SQLite WAL | A second writer/checkpointer on affected SQLite can corrupt or lose authoritative trust state. |
| state mutation -> audit append | A commit without its audit record enables repudiation and inconsistent truth. |
| live database -> backup/restore artifact | WAL state, ACL, DPAPI identity and tamper chain must remain coherent. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SC | Tampering | package-manager boundary | mitigate | No install occurs; only approved primitives from Plan 01-04 are imported. |
| T-01-15 | Tampering/DoS | SQLite 3.45.1 WAL ownership | mitigate | Exclusive owner lock, one long-lived serialized connection, no manual concurrent checkpoints, hard second-owner rejection. |
| T-01-16 | Repudiation/Tampering | audit event ordering/content | mitigate | Transactional contiguous HMAC-SHA-256 chain, DPAPI keyring and startup verification. |
| T-01-17 | Tampering/DoS | live backup/restore | mitigate | Online backup under lock, independent verification, stopped atomic swap and known-good retention. |
| T-01-18 | Information Disclosure | audit payload/backup | mitigate | Redaction before append, protected DACL, ciphertext-only secret fields and bounded artifacts. |
</threat_model>
